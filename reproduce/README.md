# Local scalar audit candidate

Run `python audit.py` with Python 3.9 or later; only the standard library is required. Compare its JSON output with `expected_results.json`; both contain the same recorded results. The JSON output includes the primary fixed and frozen policy table, all delay-only mappings, planning-derived mappings, and four separately labeled hindsight maxima: F00 shared fixed, F01 delay-only, F10 case-only, F11 case and delay. The four choices are evaluated across both cases and both delays; the comparator ranks aggregate original success O first, then aggregate M, with lexicographic enumeration breaking exact ties. It never averages per-case best differences. Planning uses Q then planning M, with 425 as the final tie break. Distinct planning and executed comparators must not be conflated.

Nesting reports F01−F00 then F11−F01, and F10−F00 then F11−F10, plus F11−F10−F01+F00. These M differences summarize the observed dataset, where every O is tied; an M contrast alone is not a general success-first utility when O differs. M is the mean of four worst-world clearances in millimetres; each cell represents two world views. Six LOW/HIGH views share underlying executions. These views are not independent samples. Case-aware choices assume case is known at installation; delay is a known schedule, not a later installation change.

Checks compare Table II's three-decimal values within 0.0005 mm, and S30/S31 six-decimal values within 0.0000005 mm. Arithmetic uses the stored decimal scalars, not rounded paper values. The source was the 16-cell scalar ledger described in the accompanying manuscript; this package contains only those records. The recomputation is a post-hoc arithmetic check, not a scientific rerun or independent reproduction. It cannot reconstruct search, physics, trajectories, classification, or raw-data validation. The original protocol's broader context and provenance are outside this candidate. License and external publication pending.
